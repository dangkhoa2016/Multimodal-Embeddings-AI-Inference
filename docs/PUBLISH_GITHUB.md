# Publishing the source on GitHub

Publish source, tests, documentation and reproducible model metadata only. Do not upload model weights, dataset image files, credentials or deployment-specific URLs. Model licenses and the dataset license are separate from this repository's MIT source license.

## Before publishing

1. Confirm `git status --short` is empty and review `git log --format=fuller` for author and committer metadata.
2. Run `bash scripts/setup.sh`, `sha256sum -c SHA256SUMS.txt` and the tracked-file security audit in the CI workflow.
3. Review `git log --all --name-status` and scan **all reachable commits**, not just the latest working tree. Keep only intended release history.
4. Ensure an authenticated GitHub account is available and confirm that the destination repository does not already contain unrelated history.
5. Create an empty destination repository without an autogenerated README, license or .gitignore.

## Push the reviewed history

Run the following from this source repository, replacing the example owner and repository name with your own:

```bash
git remote -v
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_REPOSITORY.git
git push -u origin main
```

Do not force-push an existing remote or publish any backup/reference branch containing a different history. Enable GitHub Actions, secret scanning and branch protection after publication. The source-only CI does not need Modal secrets or GPU access.

For reproducible inference, record model revision SHAs, the upstream code revision and evaluation protocol without exposing runtime credentials or account-specific URLs. See [verification evidence](VERIFICATION.md) and [operations](OPERATIONS.md).
